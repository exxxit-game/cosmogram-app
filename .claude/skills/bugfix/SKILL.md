# Исправление бага

Идти по шагам подряд, без остановок на одобрение каждого шага (решение владельца 30.09: остановки на каждом шаге стопорили работу). Спрашивать только о конкретном параметре (число, порог, формула) и о том, что увидит игрок. Параметр внутри «продолжай» не додумывать: отдельный вопрос с вариантами.

1. **Не диагностировать с нуля.** Искать по слову из симптома, файлы целиком не читать (`KNOWN-BUGS.md` весит ~150 КБ): `grep -i "<слово>"` по `.knowledge/archive/do-30-09/KNOWN-BUGS.md` и `ERROR-CATALOG.md`. Короткий чек-лист частых причин прочитать целиком: `.knowledge/archive/do-30-09/RESEARCH-2026-09-SYMPTOM-FREQUENCY-DIAGNOSIS.md`. Самая частая причина «бага» — устаревший трекер: баг уже починен в коде (~25 случаев из ~80). Проверять это первым.
2. **Симптом одной строкой до первой правки:** точное воспроизведение и точный неверный результат, из слов владельца, снимка и телефона. Вопрос вариантами задавать, только если данных правда нет. Без базовой линии потом нечего сравнивать («стало лучше или нет»).
3. **Две–четыре вероятные причины** по убыванию вероятности, проверять по порядку самому.
4. **План на один файл** одной строкой в ответе, сразу к шагу 5.
5. **Страж до правки.** Новый тест, показать, что он красный. Локально только узко, из `../cosmogram-crew`: `GAME_ROOT=../cosmogram-app node tests/guard.mjs --only=<номер>`. Полный набор локально запрещён (ноутбук виснет), он идёт на GitHub после пуша владельца.
6. **Починить ровно один файл**, показать «было → стало» целиком.
7. **Страж зелёный три раза подряд**, показать вывод.
8. **Текст коммита подготовить, коммит и пуш не делать:** коммит только по слову владельца, пуш делает он сам.

Если баг видят только на конкретном устройстве или в Telegram, сначала скилл `device-bug` (доказательство на устройстве), потом этот.
Если визуальный: правка через макет (скилл `maket`).

## Если после ~5 попыток баг не поддаётся

Не пробовать в шестой раз: причина не понята. Сказать прямо, предложить откатиться к последнему рабочему коммиту и начать разбор с шага 1.

## Необязательно

Когда баг отнесён к категории из чек-листа, можно записать в живой рейтинг: `node .claude/hooks/lib/signal-trail.mjs record <категория> <1-5> "<кратко>" --trail=bugtax --half-life-hours=720` (посмотреть: `heat` с теми же ключами). Если не записал, ничего не ломается.
