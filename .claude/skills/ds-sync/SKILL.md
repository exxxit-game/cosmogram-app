# Синхронизация дизайн-системы с игрой

Дизайн-система: https://claude.ai/artifact/WRH8uJXwRfsPkZXApf9qbg (тип Design System).
Источник правды — код игры, не система. Система только отражает игру.

## Порядок

1. **Что изменилось в игре.** `git log` по `index.html` (и `js/ui.js`, `js/ach.js`, если менялись
   карточки, которые строит JS) с даты в `tokens.json` → `meta.synced` / `meta.ref`.
   Сказать владельцу: «в системе записан коммит X, в игре сейчас Y, изменилось: …».
2. **Прочитать систему заново**, не из памяти: `Artifact` `action:"read"` с этим url —
   `project/design-system.json`, `project/tokens.json`, `project/components/bundle.css`,
   `project/README.md` и карточки затронутых компонентов. Люди могли править на странице.
3. **Правило руководства типа.** Перед записью прочитать `SKILL.md` и
   `artifact-type/reference/from-code.md` на этом же url — формат файлов и порядок сохранения
   берутся оттуда, не по памяти.
4. **Слияние, не пересборка:**
   - изменившиеся значения — обновить, точно как в коде (не округлять);
   - новые токены/компоненты — добавить с пояснением (`usage`);
   - то, чего в коде больше нет, — **перечислить владельцу и спросить**, не удалять молча;
   - пояснения, текст README и то, что добавлено на странице, — сохранить.
5. **Проверить превью локально** (headless-браузер, если он есть в этой среде; в облачной
   сессии Chromium уже установлен) и посмотреть снимки глазами до публикации. Нет браузера — сказать.
6. **Сохранить** одним вызовом только изменённые файлы; индекс
   `project/design-system.json` — последним, перечитав его прямо перед этим; обновить
   `lastChange` и `tokens.json` → `meta.ref`/`meta.synced`.
7. **Отчёт:** что обновлено, что добавлено, что предложено удалить, с какого коммита.

## Не делать

- Не править игру, чтобы «совпало с системой» — это путь `/maket`.
- Не менять цвета/логотип бренда в системе «для контраста» — отмечать проблему в пояснении.
