# Синхронизация дизайн-системы с игрой

Дизайн-система: https://claude.ai/artifact/WRH8uJXwRfsPkZXApf9qbg (тип Design System). Источник правды — код игры, система только его отражает.

## Порядок

1. **Что изменилось в игре.** `git log` по `index.html` (и `js/ui.js`, `js/ach.js`, если менялись карточки, которые строит JS) с даты в `tokens.json` → `meta.synced` / `meta.ref`. Сказать владельцу: «в системе записан коммит X, в игре сейчас Y, изменилось: …».
2. **Прочитать систему заново,** не по памяти: `Artifact action:"read"` на этот url — `project/design-system.json`, `project/tokens.json`, `project/components/bundle.css`, `project/README.md` и карточки затронутых компонентов (люди могли править на странице).
3. **Правила типа артефакта.** Перед записью прочитать `SKILL.md` и `artifact-type/reference/from-code.md` на этом же url: формат файлов и порядок сохранения берутся оттуда.
4. **Слияние, не пересборка:**
   - изменившиеся значения обновить точно как в коде (не округлять);
   - новые токены и компоненты добавить с пояснением (`usage`);
   - то, чего в коде больше нет, **перечислить владельцу и спросить**, не удалять молча;
   - пояснения, README и добавленное на странице сохранить.
5. **Как собирать карточки экранов и старых компонентов:** из живой разметки игры, а не по описанию: `references/zhivye-snimki.md`.
6. **Посмотреть превью локально до публикации** (headless-браузер, снимки глазами). Нет браузера — сказать.
7. **Сохранить** одним вызовом только изменённые файлы; индекс `project/design-system.json` последним, перечитав его прямо перед этим; обновить `lastChange` и `tokens.json` → `meta.ref` и `meta.synced`. Прочитать обратно и сверить.
8. **Отчёт:** что обновлено, что добавлено, что предложено удалить, с какого коммита, что не проверено.

## Не делать

- Не править игру, чтобы «совпало с системой»: это путь `maket`.
- Не менять цвета и логотип бренда в системе «для контраста»: отмечать проблему в пояснении.
