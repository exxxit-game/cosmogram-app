# Деплой Edge Function — продумать до, сверить после

Живой сервер — не локальный файл: отмены нет, сломанная функция ломает вход и рекорды
всем игрокам сразу. Правила CLAUDE.md 27.08, 30.08, 06.09, 18.09.2026 собраны здесь в порядок.

Исходники: `../cosmogram-crew/_supabase/functions/<имя>/index.ts` — единственный источник
правды. Проект Supabase: `cwpijvgdrrvnvldhnmbj`.

## 0. Согласие

Деплой — запись в живую систему. Только по явной просьбе владельца именно на деплой
этой функции в этой сессии. Правка кода ≠ разрешение деплоить.

## 1. До вызова — проговорить (по-настоящему, не для галочки)

- `git status` в ОБОИХ репозиториях (app и crew), не только в том, где правил файл —
  незакоммиченное в другом месте может значить забытый страж или чужую незавершённую
  работу (29.09.2026, аудит скиллов — пункт 8 чек-листа `project_checklist_nauka_dlya_deploya_23_09`).
- Какая функция, какой файл, какой коммит. Что именно изменилось (`git diff`).
- Какие параметры у вызова и какое у каждого умолчание. **`verify_jwt:false` — явно**:
  все функции проекта живут без Supabase JWT, умолчание `true` закроет функцию для игры
  (18.09.2026 — Мастерская лежала ~3 минуты).
- Если меняется константа — `node tools/where-used.mjs "<ИМЯ>"`: все места, где она
  используется (06.09.2026: `AUTH_MAX_AGE_SEC` значила два разных срока).
- Что сломается, если что-то не так, и как быстро откатить (предыдущий `index.ts` из git).

## 2. Собрать содержимое — только программно

- Содержимое для деплоя читать из файла **в этом же ходу** скриптом (`node -e` читает
  `index.ts` и отдаёт текст), не печатать по памяти и не пересказывать.
- Большие непрозрачные куски (base64, ключи, хэши) — никогда руками. Нет механического
  пути — остановиться и сказать владельцу.
- Перед отправкой проверить, что параметр содержит реальный код: нет слова `placeholder`,
  длина совпадает с файлом, первая и последняя строки совпадают. (Хук
  `guard-deploy-content.sh` страхует, но не заменяет эту проверку.)

## 3. Деплой — один вызов

Не спешить. Если только что сломал живую функцию — медленнее обычного, не быстрее.

## 4. После — два рубежа, оба обязательны

1. **Содержимое:** `get_edge_function` → сравнить с локальным файлом программно
   (побайтно или по sha256), не глазами.
2. **Живой запрос:** один безобидный вызов — для `cosmogram-sync` это
   `{"action":"public_config"}` — и проверить, что пришёл настоящий ответ, а не
   ошибка/401/таймаут. Для других функций — их самое безобидное действие; если не
   знаешь какое — спросить, не выдумывать.
3. Логи функции (`query_logs`) за последние минуты — нет ли новых ошибок.

## 5. Отчёт владельцу

Что задеплоено, какой коммит, результат сверки содержимого, ответ живого запроса.
Только после обоих рубежей писать «задеплоено и работает». Записать проверку:
`node .claude/hooks/log-claim.mjs "что утверждаю" "как проверил"`.

## Права (REVOKE/GRANT) — если деплой идёт вместе с миграцией

Новая функция в БД — `REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` в той же
миграции. После — перечитать `information_schema.role_routine_grants` и проверить `curl`
анонимным ключом (ждать `42501`), не верить `success:true`.
