# Баг на устройстве — сначала доказательство

Правило CLAUDE.md (26.08.2026): «нашёл код, похожий на причину» — гипотеза, не находка.
Похожий комментарий в коде — тоже не находка. Подтверждать на устройстве владельца.

## 1. Точно, какое устройство и контекст

Спросить вариантами (AskUserQuestion), не открытым вопросом:
- телефон: Samsung SM-A032F / Oppo CPH2631 / Oppo CPH2565 / другой;
- где: Telegram (обычный / fullscreen) / браузер;
- когда: главное меню / конкретный экран / в полёте / пауза / итоги;
- стабильно или иногда. Одной строкой записать воспроизведение и неверный результат.

## 2. Доказательство — выбрать канал измерения сразу, не «ещё одна попытка на глаз»

Если цель нельзя увидеть напрямую — строить канал измерения на первом-втором шаге
(правило «мерить, а не гадать», 26.08.2026). По порядку доступности:

1. **Телефон подключён по adb** (локальная машина владельца):
   `node tools/live-device.mjs devices` → `forward <serial>` → `pages` →
   `eval <pageId> "<js>"` (замерить `getBoundingClientRect`, CSS-переменные `--sat` и т.п.),
   `console <pageId>`, `screenshot`. Нативные элементы Telegram (кнопка «Назад»,
   шапка) CDP не видит — для них `adb screencap` / `tools/measure-title-clearance.mjs`.
2. **Почта неба (BEACON)** — письма с устройства игрока в таблицу `beacons`
   (Supabase, только чтение): в тексте каждого письма уже есть `tgv`, `full`, `stable`, `iw/ih`,
   `sat/satm/sab/sar`, сеть, fps. Найти письма этого устройства за нужное время.
3. **Запись Jam** — владелец записывает экран; через Jam читать видео, консоль и
   сетевые запросы (`getDetails`, `getConsoleLogs`, `getScreenshots`).
4. Только если ничего из этого нет — фото/скрин от владельца с конкретным вопросом
   («какая буква», «где край»), не общим «как выглядит».

## 3. Проверить, что подозреваемый код вообще выполняется там

Рисуется ли элемент на узком экране, срабатывает ли ветка в Telegram, в этом ли
режиме. Проверять тем же каналом (eval на телефоне), а не чтением кода.

## 4. Назвать гипотезу гипотезой

В чате: «гипотеза: …, проверю так: …». Не «нашёл причину», пока измерение не подтвердило.

## 5. Дальше — `/bugfix`

Страж до фикса, один файл, «было → стало», одна правка → проверка владельцем на его
телефоне → следующая. Визуальная правка — через `/maket`.
Не писать «исправлено на телефоне» без свежего реального вызова `live-device.mjs`
или подтверждения владельца (хук `device-claim-guard.mjs`).
