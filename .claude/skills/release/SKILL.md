# Релиз правки

Одна процедура вместо россыпи отдельных вызовов (16.09.2026: на каждую правку уходило 3–5 ручных шагов, и под спешкой один из них пропускался). Это финальная сборка уже согласованной правки, нового решения здесь нет.

## Что делать, по порядку

1. `git status --short` в затронутом репозитории (`cosmogram-app` и/или `cosmogram-crew`): свериться, что изменилось, прежде чем добавлять файлы.
2. Игровые файлы изменены (`index.html`, `js/*.js`, `sw.js`) — `node tools/bump-version.mjs` (один вызов вместо трёх правок). Если версия уже поднята для той же незакоммиченной пачки, второй раз не поднимать.
3. Проверка узкая, не весь набор. Страж лежит в `../cosmogram-crew`: из его папки `GAME_ROOT=../cosmogram-app node tests/guard.mjs --only=<номер или имя>`. Полный `guard.mjs` локально не запускать: ноутбук виснет (слово владельца 30.09), хук это блокирует. Полный набор идёт на GitHub после пуша владельца, ему так и сказать. Подробности: `memory/archive/feedback_guard_only_flag.md`. Страж, которого нет под правку, не придумывать: написать, что его нет.
4. Показать владельцу «было → стало» по каждому реально изменённому файлу (сверить через `git diff`, что изменено именно мной, а не параллельной сессией).
5. **Коммит — только когда владелец сказал «коммит».** Без слова остановиться на шаге 4 и подготовить текст коммита. `git add` — только явные пути, никогда `-A` и `.` (хук это блокирует).
6. Текст коммита по-русски, в стиле истории репозитория (почему, а не только что), с подписью соавтора из системного напоминания. `git push` никогда: его делает владелец.

Правка сразу в двух репозиториях (игровой файл и `guard.mjs`) — два раздельных коммита, каждый в своём репозитории.

## Чего не делать

- Не коммитить «заодно» после чужого слова про другое.
- Не писать «проверено», если проверка не запускалась: так и сказать «не запускал: причина».
