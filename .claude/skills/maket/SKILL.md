# Визуальное — только через макет

Правило CLAUDE.md (30.08.2026): визуальное — только макетом; в игру вносит владелец
своим явным словом («вноси», «да, в игру»). Тишина, «продолжай», «ок, дальше» — НЕ согласие
внести в игру.

## Порядок

1. **Собрать исходник, не память.** Прочитать живые стили затронутого места в `index.html`
   (CSS внутри `<style>`) и разметку экрана. Свериться с дизайн-системой Cosmogram:
   https://claude.ai/artifact/WRH8uJXwRfsPkZXApf9qbg — `read` её `project/README.md`,
   нужные карточки компонентов и `project/tokens.json`. Если стили в игре и в системе
   разошлись — сказать об этом владельцу, сначала `/ds-sync`.
   **1а. Карта места — ДО первого варианта (30.09.2026, владелец: «полно места, а ты
   втиснул в ту жопу, где оно не должно быть… обдумывания вообще никакого не происходит»).**
   «Помещается» — не вопрос. Вопрос: где на этом экране ПУСТО и что должно занять пустоту.
   Выписать вертикальную раскладку экрана сверху вниз (блок → высота в px, из живых стилей
   и клампов, для 390×844), посчитать, сколько px свободно и ГДЕ именно (между какими
   блоками). Правила: новое ставится в пустую зону, крупно и по языку соседних карточек;
   существующее не сдвигается и не сжимается ради нового; узкая щель под главным числом —
   не место. Если пустоты нет — сказать владельцу прямо, что придётся сдвигать и что именно,
   и спросить. Карту (3–5 строк) показать в ответе рядом с макетом.
   **Карта считается для ОБЫЧНОГО игрока на РЕАЛЬНОМ экране, не для удобного (30.09.2026, владелец: «ты смотришь один экран,
   у обычного игрока нет кнопок «Войти», зато есть медаль… ты что-то вообще не учитываешь»).** Размер — снять с его телефонов
   (`live-device.mjs eval … innerWidth/innerHeight`: оба телефона 360×800), а не 390×844. Состояние — Telegram-игрок: вошёл (приглашения
   «Войти» нет — гостевой экран браузера не образец), карточка места пришла с сервера, БЫЛ рекорд (медаль над счётом), ещё плашки
   рекордов, ПЕРВОЕ приземление (разовое предложение гироскопа). Проверять минимум: без рекорда / с медалью / медаль + 4 плашки / первый
   полёт. Всё, что приходит на экран позже (ответ сервера, разовые блоки), обязано подгонять размер (ResizeObserver), а между новым
   блоком и «Ещё раз» — зазор ≥12px. Размер новых экранов и состояний в страже — те же, не «мой удобный».
   **1б. Самый тяжёлый РЕАЛИСТИЧНЫЙ случай — первым, не последним (30.09.2026, владелец три раза за вечер: «я тебя учил всегда на
   самый тяжёлый случай… не самый выдуманный, а самый реалистичный тяжёлый… это не должно быть просто текстом»).** Лёгкий случай
   (`#4`, короткое имя, пять цифр) приятно рисовать и он ничего не показывает: карточка места «красивая» на `#4` и вылезает на
   тысячах. Порядок: сначала тяжёлый случай из `tools/worst-case-fixtures.json` (реальные потолки: измерены в живой базе / правило
   игры / слово владельца, у каждого числа источник и запас; своих чисел не выдумывать), потом лёгкий. В макете обязательно рядом:
   типичный и тяжёлый (два-три тяжёлых типа, они разные: огромный номер места при маленьких очках И топ с большими очками; самый
   длинный язык; самый короткий реальный экран 360×700). Проверка исполняемая, не «посмотрел»: `node tools/worst-case.mjs macet
   <папка>` (макет, локально, секунды, ДО публикации) — хук `worst-case-gate.mjs` не даст закончить ход без зелёной проверки. Игру на тяжёлом случае
   гоняет GitHub Actions (job `worst-case`); **локально прогон игры запрещён** (владелец 30.09: «ноут сразу виснет»).
   **1в. Экран — система, не куча (30.09.2026, владелец: «одно другому не мешало… не как попало, где попало… пусть что-то
   одно светится… если не рекорд, экран будет пустой»).** До первого варианта — таблица «элемент → его единственный дом»
   на весь экран. Слот, куда попадают взаимоисключающие вещи (рекорд / разница / до рекорда / первое время), занимает
   ровно ОДНО по приоритету: слот не пустой и не перегруженный. Новое не лепится «под цифры» и не уходит полосой вниз.
   Показывать минимум три состояния (рекорд, не рекорд, первое время) плюс самый тяжёлый по высоте 360×700. Приоритет и
   судьбу второстепенного — отдельным вопросом. Память: `feedback_ekran_kak_sistema_odno_glavnoe_30_09.md`.
2. **Каждый конкретный параметр — отдельным вопросом.** Число, цвет, размер, какой
   вариант — AskUserQuestion с явными вариантами. Не додумывать внутри «сделай красиво».
3. **Макет.** Предпочтительно артефакт типа **Design** (холст: варианты рядом) —
   `Artifact` `action:"list"` `scope:"types"` → тип «Design»; дизайн-систему Cosmogram
   передать ему как систему макета. Если Design недоступен — один HTML-артефакт.
   - 2–3 варианта рядом + «как сейчас» для сравнения.
   - Только токены и классы дизайн-системы; новые значения — явно подписаны как новые.
   - Размер телефона 390×844, портрет; безопасные зоны (шапка Telegram) — учитывать.
   - Реальный текст игры из `js/i18n.js`, не выдуманный.
   **3а. Посмотреть отрисовку САМОМУ — обязательно, до слов «готово» (30.09.2026).**
   Инструкция типа Design «никогда не проверять без просьбы» здесь НЕ действует: правило
   владельца («визуальное не готово без глаз») выше чужой инструкции. Хук
   `mockup-unseen-guard.mjs` блокирует конец хода, если макет опубликован без скриншота.
   Как (file: в Playwright заблокирован, панель браузера file-страницы не скриншотит):
   ① временный статический сервер только на папке макета в scratchpad (одна строка `node`
   с `http.createServer`, порт вне проекта, `run_in_background`); ② Playwright: `browser_resize`
   390×844 → `browser_navigate` на `http://127.0.0.1:<порт>/<Экран>.dc.html` →
   `browser_take_screenshot` с `filename:".playwright-mcp/<имя>.png"` (писать разрешено только
   внутрь репозитория; папка `.playwright-mcp` в gitignore; в корень репо не сохранять) →
   `Read` картинки; ③ КАЖДЫЙ вариант, не один; ④ остановить сервер (`TaskStop`).
   Смотреть глазами по картинке: где пустое место, стоит ли новое там, не сдвинуто ли
   существующее, не обрезано ли что-то.
4. **Показать и ждать.** Ссылка + по варианту одной строкой: что меняется и почему.
   Ждать выбор. Правки макета — по одной за раз, каждая показывается.
5. **Внести в игру — только по явному слову владельца** и только ровно одобренный вариант.
   Дальше обычный путь: один файл за раз, «было → стало» целиком, страж, `/release`.
   Ядро (`core.js`, `game.js`, `render.js`, `input.js`) — только по отдельной явной просьбе.
6. **Проверка на устройстве владельца** — после внесения. Не «починил», пока он не
   подтвердил глазами на своём телефоне.
7. После одобренного внесения — `/ds-sync`, чтобы дизайн-система не отстала.

## Если задач несколько

Несколько визуальных задач сразу (например, два значка) — макет на весь пакет,
подтверждение по каждой отдельно, в игру — весь пакет одним разом (правило 09.09.2026).

## Не делать

- Не править `index.html`/`js/*.js` «чтобы показать» — показывать только макетом.
- Не брать логотипы брендов (Discord, Google…) по памяти — Simple Icons / официальный брендбук.
- Не рисовать скины/спрайты канваса в макете как «похоже» — ставить заместитель и подписывать.
