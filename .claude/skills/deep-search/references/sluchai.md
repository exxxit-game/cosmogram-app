# Случаи, из-за которых появился скилл «Глубокий поиск»

Вынесено из `SKILL.md`. Читать, когда нужно увидеть, как выглядит «обычный путь, который не сработал».

## 28.09.2026

- **Музыка на телефонах.** Три дня чинили синтезатор по кусочку, хотя с первого замера было видно, что сам подход (сочинять звук на телефоне) не тянет слабое железо. Надо было сразу спросить «какие вообще есть семейства решений», а не «как облегчить этот».
- **Сжатие.** Предложил 64/96/128 кбит/с «послушай, что лучше»: параметр от балды, без метода. Правильный путь нашёлся после вопроса «из чего состоят наши данные»: вся 6-минутная музыка — один круг из 8 тактов, значит хранить слои по 15 с, а не 6 минут смеси; без потерь 24 МБ стали ~7 МБ.
- **«Две разные песни».** Усреднённое мерило сказало «похоже», ухо сказало «нет». Мерило выбирать под вопрос (такт за тактом, а не среднее по файлу).

## 29.09.2026: скилл не только про звук

Владелец: «этот скилл написан слишком узко, а триггерится широко». Триггерные фразы («подумай хорошо», «нестандартно», «раз и навсегда») ловят любое решение, включая архитектуру инструментов, хуков, памяти. Пример того же вечера: хук `claim-check-hook.mjs` («ловить в тексте слово «готово»») не срабатывал на непредвиденных формулировках; вместо шестого патча регулярки поиск на английском нашёл паттерн индустрии («never block on regex alone: AND-gate with tool evidence») и по цене ошибки (дорогие действия — деплой, SQL, git commit — обходятся дороже дешёвой правки файла) получился гибрид: слова для дешёвого, факт вызова для дорогого. Семейство «соседние дисциплины» сработало здесь для паттернов проверки агентов и журналов.
