# Git-конфликт: сравнить обе стороны, не брать вслепую

Владелец работает в GitHub Desktop в том же чек-ауте, это обычный режим проекта. Инциденты одного класса случались 03.09 (дважды) и 29.09.2026.

## 0. Диагноз до паники

- `git status`; при unmerged paths прочитать `.git/MERGE_MSG` и `git log --oneline origin/main -5`: что и откуда мержится (обычно Pull в GitHub Desktop, а не сессия Claude).
- Правки «пропали» без моего `commit`/`reset`/`stash` — прежде чем переписывать заново, проверить `git stash list`. GitHub Desktop умеет тихо застэшить незакоммиченное (`memory/archive/feedback_github_desktop_silent_stash.md`).

## 1. Ядро только по отдельной просьбе

Конфликт в `core.js`, `game.js`, `render.js`, `input.js` — это тоже «трогать ядро», даже если правка механическая. Нужно явное «разреши конфликты» на этот конкретный мерж; на будущие оно не переносится.

## 2. Обе стороны, не вслепую

Прочитать HEAD и входящий блок целиком и понять разницу по сути:
- **Только цифры** (версия, хвосты `?v=`): обычно взять более новое число и потом поднять версию; озвучить владельцу.
- **Реальная логика** (переименованная функция, две фичи в одном месте): всегда отдельный вопрос с вариантами (AskUserQuestion), ничего не додумывать.
- Часто это один и тот же замысел в двух формулировках: сравнение по содержанию ловит это быстрее, чем разбор по маркерам.

## 3. Разрешать через Edit, не через Bash

Автоматический классификатор блокирует Bash-скрипты на файле с активным конфликтом даже после «да» владельца и блокирует повторно (`memory/archive/feedback_classifier_blocks_conflict_scripts.md`). Не продавливать тот же вызов: разрешать точечно через `Edit` (`old_string` — весь блок с маркерами, `new_string` — выбранное).

## 4. После разрешения

1. `grep` на маркеры: нигде не осталось.
2. Синтаксис: `node --check` на `.js`, `bash -n` на `.sh`.
3. Правка игрового файла — `node tools/bump-version.mjs` (версия поднимается после любой правки, мерж не исключение).
4. Страж только узкий, из `../cosmogram-crew`: `GAME_ROOT=../cosmogram-app node tests/guard.mjs --only=<номер>`. Полный локально запрещён (ноутбук виснет), он идёт на GitHub после пуша владельца; сказать ему об этом.
5. Коммит «разрешение конфликта» — только по слову владельца, `git add` явными путями. `git push` никогда.

## 5. GitHub Desktop уже открыт с тем же слиянием

Не коммитить через CLI параллельно с открытым окном: два инструмента на одном `.git` рискуют десинхронизацией. Файлы разрешить можно (GUI подхватит с диска), а финальный коммит либо после слова владельца, либо оставить ему кнопку в его окне.
