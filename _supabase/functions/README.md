# Сервер Космограммы — исходники

Здесь живут исходники всех edge-функций Supabase. До 13 августа 2026 их не было
нигде, кроме самой Supabase: единственной копией был развёрнутый артефакт.

## Зачем это отдельная папка, а не «где-то в облаке»

Симптом: чтобы поменять двадцать строк в `cosmogram-sync`, приходилось пересказывать
весь файл на 830 строк — потому что функция разворачивается целиком, а исходника на
диске не было. Пересказ большого файла и есть главный риск такой правки.

Корень: серверный код не был под версионным контролем. Отсюда всё остальное —
нет истории, нет отката, нет способа увидеть расхождение между «что мы думаем, что
развёрнуто» и «что развёрнуто».

Лекарство: держать исходники здесь. Тогда правка — обычный diff, а разворачивание
становится механическим действием, а не переписыванием.

Рождённый закон: **у развёрнутого кода обязана быть копия в репозитории.**
Артефакт — не исходник. Если единственная копия живёт там, где её нельзя
посмотреть построчно, любая правка превращается в пересказ по памяти.

## Что где

| Функция | Что делает | Живая? |
|---|---|---|
| `cosmogram-sync` | таблица рекордов, дуэли, призраки, дневник борта, карточка, статус | да, главная |
| `cosmogram-top` | публичная витрина таблицы, только чтение — **временная**, см. ниже | да |
| `cosmogram-beacon` | «Почта неба»: письма об ошибках и дневник гостя | да |
| `cosmogram-daily` | Трасса дня: посадки, лента чемпиона, знак звезды | да |
| `cosmogram-app` | раздача мини-приложения | ни разу не читалась в аудите |
| `cosmogram-mirror-sync` | отключена (v1.108.1), отвечает 410 | нет, но дверь открыта |
| `ct-test` | отключена (v1.280.0), отвечает 410 | нет, но дверь открыта |

`cosmogram-top` заведена 13.08.2026 как обходной путь: правка должна была жить в
`cosmogram-sync` (патч уже лежит в этой папке), но развернуть ту можно только целиком —
860 строк одним куском. Как только появится Supabase CLI, чтение переезжает внутрь
`cosmogram-sync`, а `cosmogram-top` удаляется. **Это долг, а не архитектура.**

Две отключённые функции отключены изнутри, но **сами функции по-прежнему существуют и приняли бы
запрос**: полное удаление делается только в панели Supabase. Это долг.

## Почему папка начинается с подчёркивания

Репозиторий раздаётся как сайт через GitHub Pages: всё, что в нём лежит, доступно любому
по прямой ссылке. Секретов в этих файлах нет — ключи живут в таблице `config` внутри базы,
и код читает их оттуда. Но здесь видны пороги правдоподобия, окна антиспама и вся логика
проверки результата, то есть карта того, что именно нужно обойти.

GitHub Pages собирает сайт Jekyll'ом, а Jekyll **не публикует папки, начинающиеся с `_`**.
Поэтому `_supabase`: в репозитории есть, в истории есть, на сайте — нет.

Важно: если когда-нибудь в корень положат файл `.nojekyll`, Jekyll выключится и папка
станет публичной. Тогда её надо будет унести в отдельный закрытый репозиторий.

## Как разворачивать

Supabase CLI ищет функции строго в `supabase/functions/...`. Перед разворачиванием
переименуй папку локально (`_supabase` → `supabase`), разверни и верни имя обратно:

    mv _supabase supabase
    supabase functions deploy cosmogram-sync
    mv supabase _supabase

Все шесть живут с `verify_jwt:false` — защита у каждой своя, внутри кода. Разворачивая,
не забывай про этот флаг: включённый JWT закроет функцию для игры.

## Сверка

Развёрнутое и то, что лежит здесь, могут разойтись — если кто-то правил функцию через
панель. Это тот же закон 11 («залито ≠ роздано ≠ работает»), только про сервер:
после любой правки сверяй, что развёрнутое совпадает с этим файлом.
