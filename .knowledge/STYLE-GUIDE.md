# ✍️ Cosmogram — Style Guide & Coding Standards

> Соглашения по коду, инцидент-комментарии, Story-Comments, Conventional Commits, Zero-Allocation.
> Единственный стандарт после слияния баз: **имена в коде — английские, комментарии — русские.**

---

## 1. Общие принципы

1. **Читается как книга:** чистый модульный код без сборщиков и фреймворков. Один модуль ≈ 200 строк (максимум 300).
2. **Изоляция движка от DOM:** модули физики/математики/рендера не трогают `document`/`window`, кроме `render.js`, `input.js`, `ui.js`.
3. **Zero-GC в тике:** запрещено возвращать новые объекты `{x, y}` или массивы в тике. Поля меняются по месту, используются scratch-буферы и статические пулы.
4. **Инвариант детерминизма:** любой спавн и любая случайная величина — только внутри `withTrack(kind, fn)`.

## 2. Именование

| Сущность | Соглашение | Пример |
|---|---|---|
| Глобальные системы | `PascalCase` | `Store`, `BB`, `BEACON`, `Steering` |
| Центральное состояние | одиночная заглавная | `S`, `L` (локализация) |
| Функции и методы | `camelCase`, глагол в начале | `spawnObstacle()`, `hitPlane()` |
| Константы и капы | `UPPER_SNAKE_CASE` | `POOL_CAP`, `PARTICLE_CAP`, `STEP` |
| Таймеры/флаги табло | префикс `_mh` / `_` | `_mhTime`, `_mhOnce` |
| Координаты | `x, y, vx, vy, bank` | `plane.x`, `plane.bank` |

**Двухуровневое именование (согласовано 22.08.2026).** Для НОВОГО кода: короткие имена
`dt`/`dx`/`dy`/`vx`/`vy`/`x`/`y`/`i`/`j`/`k` допустимы только внутри горячего цикла
(`update()`/`render()` и их прямые вызовы). Везде за пределами горячего цикла — только
описательные имена, короткие сокращения там неуместны.

**Язык:** идентификаторы и имена — **на английском**; комментарии — **на русском**. (Вариант «переменные на русском» из старой базы отменён — он противоречит кодовой базе.)

**Решение по `S`/`Q`/`AC` (согласовано 22.08.2026).** Глобальное переименование этих трёх
однобуквенных имён в защищённых файлах ядра — отменено: второе мнение оценило риск в
638+ правок по всей кодовой базе, что не оправдано для чистой читаемости. `S`, `Q`, `AC`
остаются как есть навсегда, если не будет отдельного нового решения. Читаемость закрывается
комментарием-расшифровкой в начале файла, где они впервые объявлены, не переименованием.

## 3. Структура модуля

Каждый файл следует шаблону:

```javascript
'use strict';
/* ============================================================
   НАЗВАНИЕ МОДУЛЯ: краткое описание
   Версия: v1.400.2
   ============================================================ */

/* ---------- Константы ---------- */
const MAX_ASTEROIDS = 50;

/* ---------- Состояние ---------- */
let activeAsteroids = [];

/* ---------- Функции ---------- */
function spawnAsteroid(x, y) {
  // ...
}

function updateAsteroids(dt) {
  // ...
}

/* ---------- Экспорт (глобальный) ---------- */
window.ASTEROIDS = {
  spawn: spawnAsteroid,
  update: updateAsteroids
};
```

**Новые небольшие/общие JS-файлы (согласовано 22.08.2026).** Для файлов вне горячего цикла
(не `game.js`/`render.js`/`core.js`/`input.js`, а вспомогательные модули) — добавлять
`// @ts-check` первой строкой и JSDoc-типы на публичные функции. Это нулевая сборка: не
требует TypeScript, компилятора или шага сборки, только аннотации, которые понимает
редактор. Плюс баннер-комментарий «оглавление» вверху файла (как в шаблоне выше) и правило
«один файл = одна забота» — не смешивать состояние, рендер и I/O в одном модуле.
