  вслепую — только зафиксировано как открытый вопрос.

- **`vh_underreport: 34px` — САМОИСПРАВЛЕНИЕ: мой более ранний вывод «чинить нечего» был
  неверным, вот честный пересмотр в тот же день (03.09.2026, iOS, версия 1.478.48→1.478.56,
  устройство — iPhone 16, владелец подтвердил живьём).** Сначала я написал, что `cssH =
  Math.max(rt.viewportStableHeight, window.innerHeight)` (`core.js:1271-1273`) уже полностью
  защищает от заниженного `viewportStableHeight`, и сигнал — просто безобидный измеритель.
  Это была ошибка: `Math.max` защищает только JS-переменную `cssH`, которую резервирует под
  себя КАНВАС (`canvas.style.height=cssH+'px'`, `core.js:1340`) — но НЕ защищает остальные
  экраны игры. Владелец прислал два скриншота с iPhone 16 (экран итога полёта и сама игра) —
  на ОБОИХ, всегда (не иногда), сверху под шапкой Telegram и снизу под контентом видна
  сплошная чёрная полоса — то есть само расхождение видно глазом, не только в телеметрии.
  **Вероятный настоящий механизм (не подтверждён кодом до конца, но собран из трёх фактов):**
  1. `#game{position:fixed;inset:0}` и `.overlay{position:fixed;inset:0}` (`index.html:198,201`)
     — ни один из них не получает явную высоту от JS (только у канваса есть `canvas.style.height`,
     у `.overlay`-экранов, включая экран итога полёта, — нет вообще). `position:fixed;inset:0`
     без явной высоты растягивается по LAYOUT viewport браузера/WebView, а не по фактически
     видимой (visual) области — если у Telegram на iOS расходятся эти два viewport (ровно то,
     под что и был поставлен `vh_underreport`), `.overlay`-экраны у уедут за пределы видимого,
     и родится ровно такая симметричная полоса сверху и снизу, что видна на обоих скриншотах.
  2. `window.visualViewport` — API браузера, созданный именно для разбора layout vs visual
     viewport — нигде в `js/*.js` не используется (проверено grep, ни одного совпадения).
     Это стандартный путь чинить именно такой класс расхождения на iOS Safari/WebKit-WebView.
  3. Симметричность (сверху И снизу, не только снизу) не объясняется одной лишь нехваткой
     высоты канваса (`canvas` при `position:fixed;inset:0` с явной высотой должен по CSS-спеке
     прижаться к верхнему краю — over-constrained `top`+`height` побеждает `bottom`, — то есть
     от одной лишь усечённой канвы полоса ожидалась бы только СНИЗУ). Двусторонняя полоса
     сильнее указывает на разницу layout/visual viewport на уровне всей страницы, а не только
     на просчёт `cssH`.
  **Статус: правдоподобная гипотеза с реальным подтверждением на устройстве, не финальный
  диагноз** — по правилу проекта не чиню вслепую. Не проверено: действительно ли `.overlay`
  экраны (не только канвас) реально короче видимой области именно из-за viewport-расхождения,
  или полоса — что-то третье (например, WebView Telegram сам рисует чёрный фон под/над своим
  контентом при недогрузке). Следующий шаг для владельца/другого диалога — либо живой замер
  `window.visualViewport.height` vs `window.innerHeight` на этом же iPhone, либо (если числа
  подтвердятся) добавить `visualViewport` в расчёт `--sat-menu`/`resize()` и/или дать
  `.overlay`-экранам ту же явную защиту высоты, что уже есть у канваса.
- **`[fps:X lvl:Y tier:Z] Script error.` — непрозрачная ошибка без адреса, источник не
  установлен (найдено 03.09.2026, живой сигнал Linux aarch64, версия 1.478.56).** Формат
  собирается в `skymail.js:260-264`: слушатель кладёт `e.filename+':'+e.lineno+':'+e.colno`
  перед текстом, но здесь адрес пуст — сам браузер стёр детали. Это стандартное поведение
  спецификации HTML для ошибки, которую браузер не может признать «тем же источником», что
  документ: `e.message` заменяется буквальной строкой `"Script error."`, `filename`/`lineno`/
  `colno` обнуляются, `e.error`/стек недоступны. Все `<script defer src="js/*.js">` в
  `index.html` — того же домена, сама игра формально не виновата; ошибка родилась либо в
  постороннем инжектированном скрипте (расширение браузера, антивирус, переводчик страницы),
  либо во встроенном WebView-хосте — у Telegram уже задокументирован похожий класс поведения:
  мост оборачивает каждый колбэк в свой `try/catch` и глотает ошибку целиком, не пропуская её
  дальше (`core.js:39-48`, «Мост не глотает»). Установить конкретный источник по одной этой
  телеметрии нельзя — данных недостаточно. Два нереализованных варианта для решения владельца,
  не выбраны и не сделаны:
  1. Добавить в контекст письма `document.referrer`/`window!==window.top` (запущена ли

  2. Считать одиночные немые «Script error.» без адреса телеметрическим шумом и не засчитывать
     их в `errCount`/не слать открытку вовсе — раз локализовать источник невозможно, они не
     несут действия, только раздувают счётчик ошибок в «Почте неба».
