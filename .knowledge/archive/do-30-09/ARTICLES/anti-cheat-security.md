# 🛡️ Защита от читерства и криптографическая честность в веб-играх

> **Источник:** Gamasutra Anti-Cheat & Web Cryptography Standards  
> **Статус:** 🔴 Фундамент серверного контура `sync.js` и защиты дуэлей

---

## 1. Клиент — среда без доверия (Zero Client Trust)

В веб-играх клиентский код JavaScript открыт для инспекции и модификации в DevTools. Любая попытка шифровать рекорды на клиенте бесполезна.

### Архитектурные принципы Cosmogram:
1. **Планка дуэли живёт на сервере:** Ссылка-вызов не содержит очков (`https://cosmogram.app/duel?id=xyz`). Значение планки проверяется исключительно сервером Supabase Edge.
2. **Верификация потока ленты (Replay Validation):** Сервер не принимает запись рекорда, если входной поток команд не воспроизводит заявленную дистанцию в эталонной детерминированной симуляции.
3. **Потолок `SCORE_CEIL`:** Жесткий фильтр заведомо невозможных очков (>5 000 000) до отправки в базу.
4. **Невозможность отдачи нечестного призрака:** Сервер не отдает призрак с результатом, превышающим верифицированный максимум.

## 2. Безопасная генерация криптографических токенов

```javascript
// Генерация CSRF state для OAuth и сессионных меток:
function generateSecureState(len = 32) {
  const bytes = new Uint8Array(len);
  crypto.getRandomValues(bytes);
  return Array.from(bytes, b => b.toString(16).padStart(2, '0')).join('');
}
```

## 3. Чеклист защиты честности соревнований

- [ ] В URL-ссылках дуэлей отсутствуют числовые значения рекорда.
- [ ] Все вызовы рекордов подписываются `initData` Telegram с HMAC-SHA256 проверкой на бэкенде.
- [ ] Офлайн-записи сохраняются в очереди `Store` и отправляются с сохранением монотонности.

## 4. Таксономии и чеклист эксплойтов (сверено с внешними источниками)

- **Для JS-игр memory-editing нерелевантен** (цитата из гайда GuidedHacking: «JS
  компилируется во время выполнения, бинарника для правки нет»). Реальная поверхность
  атаки — DevTools-консоль и перехват сетевых запросов. Поэтому защита правильно
  стоит на сервере, а не на обфускации клиента.
- **OWASP Game Security Framework v0.5.1** (начат янв. 2025, статус Incubator) —
  ближайшая готовая таксономия. Уровень 1 «достаточен для одиночных игр с таблицей
  рекордов». Ключевые секции: V1 (trust boundaries, авторитетный сервер), V3
  (антитамперинг, безопасное локальное хранилище), V5.3/V5.4 (валидация игровой
  логики и ввода), V6.2 (боты/автоматизация).
- **Yan & Randell (NetGames '05)** — академическая классификация читерства; категория A
  «Cheating by Exploiting Misplaced Trust» — точная модель угрозы клиентской аркады.
- **Чеклист эксплойтов для тестирования своей же системы:** (a) прямая инъекция счёта
  из консоли, (b) невозможные значения (отрицательное время, сверхчеловеческий счёт),
  (c) повтор отправки одного результата, (d) подмена запроса в пути, (e) правка
  localStorage/памяти. Пример: p410n3 обошёл клиентский кап 27 секунд значением 26.9999.
- **Macklon et al., «A Taxonomy of Testable HTML5 Canvas Issues»** (IEEE TSE 2023,
  DOI 10.1109/TSE.2023.3270740) — единственная эмпирическая база категорий визуальных
  багов Canvas (2 403 отчёта, 123 проекта) + 24 инжектированных бага в ASE 2022.
  Оговорка: «производительность» в ней всего 5% — выборка по опенсорсу, для
  слабого Android вес этого класса выше; сверять со своим профилированием.
- **Готовой базы багов Telegram Mini Apps не существует** — ближайшее: официальная
  документация + tma.js. Значит, собственный чеклист (этот файл + TELEGRAM-GOTCHAS)
  ценнее любого агрегатора.
- **FEMITBOT (CTM360, апрель 2026):** мошенники уже подделывают «верифицированную
  интеграцию» — 60+ доменов, 146+ ботов, собственные HMAC-подписи. Урок: доверять
  только серверной проверке initData; клиентский «verified»-флаг — не доказательство.
- **Уже сделано правильно (проверено по коду 1.284.2, не трогать):** постоянное по времени
  сравнение подписей во всех функциях; `HMAC('WebAppData')` для initData и `SHA256(bot_token)`
  для Login Widget не перепутаны; секреты не покидают базу, в клиенте только publishable-ключ;
  потолки скорости выведены из физики, а не на глаз; перечитывание после триггера; атомарный
  claim через `ON CONFLICT DO NOTHING`; ни одной строки сырого SQL.
