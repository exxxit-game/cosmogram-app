## Находки

### 1. `#pauseBtn` (единственная кнопка паузы в полёте) — 32×32px портрет / 28×28px альбом, ниже собственного порога проекта «36px, легче попасть пальцем» для ±/круглых кнопок, и вне зоны действия обоих стражей тач-зон/переполнения (`index.html:1000, 3483`)

```css
/* index.html:1000 */
#pauseBtn { width:32px; height:32px; border-radius:50%; flex:none; /* v1.101.0: прибор кабины —
  своё стекло, своё кольцо; 28.08.2026: было 42px — владелец, «большая очень» рядом со звёздами
  (17px) и жизнями (24px) */
/* index.html:3483, альбомная ориентация */
#pauseBtn { width:28px; height:28px; } /* 28.08.2026: было 34px, следом за портретной правкой */
```

`#pauseBtn` — единственный способ поставить полёт на паузу (`js/ui.js:3181`,
`wireOn('pauseBtn','click',pauseGame)`), виден на `#topHud` в КАЖДОМ полёте у каждого игрока —
вероятно, самая часто нажимаемая иконка-кнопка во всей игре после самого руления. Она не входит
в перечень экранов, которые проверяют стражи 194/195 (`cosmogram-crew/tests/guard.mjs:9667-9676,
9729-9738` — восемь статичных оверлеев: меню/ангар/достижения/настройки/топ соревнований/
кузница/равноправие/благодарность), потому что `#topHud` — не один из этих оверлеев, а
постоянный HUD поверх самого полёта; и не входит в общий селектор `SEL` этих стражей
(`.btn,.angarIt,.topIt,.achIt,.setRow,.heroCard...,.achRow,.forgeChip,.forgeSegBtn,
.relayMineBtn,.angarTab,.menuBack`), потому что у кнопки нет ни одного из перечисленных
классов — только собственный `id`. `grep -n "pauseBtn" guard.mjs` — единственное упоминание
(`guardPointerLockIgnoresMenuButtonClicks`, строка ~6964) проверяет поведение Pointer Lock при
клике по кнопке, не её размер. Ни один страж размер `#pauseBtn` не измеряет.

**Почему это находка, а не гипотеза**: чистое чтение CSS, число не спорное — 32px и 28px меньше
36px арифметически, без нужды в живом устройстве. Важнее — это не «число на глаз», а прямое
несоответствие **собственному, свежему, явно сформулированному стандарту проекта**: комментарий
у `.grAmtBtn` (`index.html:1584-1595`, тот же вечер) прямо называет 36px «уже отдельно принятым
владельцем 15.09.2026 порогом "крупнее, легче попасть пальцем" (36px, тот же номер, что уже
стоит у других ±/round-кнопок игры)» — то есть проект сам знает и применяет этот порог к
круглым/±-кнопкам, но `#pauseBtn` (круглая кнопка, тот же визуальный язык «планета-кольцо», что
и `.menuBack` — см. `AI-DECISION-REGISTRY.md` V1) остался на 32/28px, ниже собственной планки.

**Второй заход**: `.menuBack` (`index.html:1016`, «Назад» почти на каждом экране — 14
использований, все с `aria-label`) — та же круглая кнопка той же V1-стилистики, тоже 32×32px,
но она хотя бы формально входит в `SEL` стража 194, проходит проверку только потому, что порог
стража — юридический минимум WCAG 2.2 SC 2.5.8 (24×24px), а не собственный 36px-стандарт
проекта. `#pauseBtn` не проходит даже эту минимальную проверку, потому что её физически никто не
запускает.

**Честная оговорка**: не нарушение закона (32/28px выше юридических 24×24) и не новая гипотеза о
конкретном визуальном баге на устройстве владельца — структурный пробел между собственным
явно заявленным стандартом проекта и одной конкретной, самой частой в игре кнопкой, плюс дыра в
покрытии стражей, которая не даст узнать, если размер случайно уменьшится ещё.

### 2. `#smoothCap` («Плавность», подпись полосы в полёте) — эффективная непрозрачность текста вдвое ниже соседней подписи «Расстояние» на том же HUD (`index.html:1211-1217`)

```css
/* index.html:1211 — «Расстояние» */
#distHud { ... color:rgba(188,210,255,.75); ... }
/* index.html:1215 — базовый класс подписи обеих пилюль */
.pillCap { ...; opacity:.7; font-weight:400; }
/* index.html:1217 — «Плавность» */
#smoothCap { color:rgba(188,210,255,.4); }
```

`#distCap`/`#smoothCap` оба наследуют `.pillCap` (`opacity:.7`), но `#smoothCap` дополнительно
задаёт собственный `color` с альфой `.4`, тогда как `#distHud` (родитель числа рядом с `#distCap`)
держит альфу `.75` на **том же цвете** `rgba(188,210,255,…)`. CSS `opacity` элемента и альфа-канал
его `color` перемножаются в итоговую видимую непрозрачность: `#distCap` (через `#distHud`-ветку) —
примерно `.75×.7≈0.53`, `#smoothCap` — примерно `.4×.7≈0.28`, то есть подпись «Плавность» почти
вдвое менее заметна на глаз, чем визуально параллельная ей подпись «Расстояние» в том же ряду
HUD, при одинаковом коде цвета.

**Почему это находка, а не гипотеза**: числа взяты прямо из CSS, арифметика перемножения альф —
не гипотеза о рендере, а факт композиции CSS-свойств. **Честная оговорка о серьёзности**: сам
текст лежит поверх живого canvas-неба (день/ночь/облака) — точный WCAG-коэффициент контраста
(нужна формула `(L1+0.05)/(L2+0.05)`, как уже принята в `COLOR-REGISTRY.md`) для ДИНАМИЧЕСКОГО
фона честно посчитать нельзя без живого рендера, тот же принцип осторожности, что уже
зафиксирован в `COLOR-REGISTRY.md` («даже 3:1+ не гарантия при полупрозрачном свечении»). Но
асимметрия между двумя соседними подписями одного ряда — не гипотеза, а проверенное расхождение
в самом исходнике: если создатель кода не имел в виду «Плавность» менее важной информацией, чем
«Расстояние», сейчас она читается именно так.

**Второй заход**: `grep -in "smoothCap\|distCap" cosmogram-crew/tests/guard.mjs` — ни одного
совпадения; ни один из 329 стражей не проверяет цвет/альфу текстовых подписей HUD. Не
задокументировано в `KNOWN-BUGS.md`/`ACCESSIBILITY-GUIDE.md`.

### 3. `#calLamp` (лампочка статуса синхронизации в Настройках) — состояние передаётся ТОЛЬКО цветом, текстовая альтернатива есть в коде, но работает только по наведению — на сенсорном экране (у игры ~79% игроков, `RESEARCH-2026-09-...RASPREDELENIE-USTROYSTV`) наведения не бывает (`index.html:1696-1700, 4088`; `js/ui.js:3192-3200`)

```css
/* index.html:1698-1700 */
.calLamp[data-state=green] { background:#4ade80; ... }
.calLamp[data-state=amber] { background:#fbbf24; ... }
.calLamp[data-state=red]   { background:#f87171; ... }
```
```html
<!-- index.html:4088 -->
<div class="setRow" id="setCalibBtn" role="button" tabindex="0">
  <span id="setCalibTxt">Калибровка наклона</span><i id="calLamp" class="calLamp" data-state="red" title=""></i>
</div>
```
```js
// js/ui.js:3193-3200
function calLampUpdate(){
  const l=$('calLamp'); if(!l) return;
  const st=(tg&&web)?'green':((tg||web)?'amber':'red');
  l.dataset.state=st;
  l.title=(st==='green'?L.lampGreen:(st==='amber'?L.lampAmber:L.lampRed));
}
```

Восьмипиксельный цветной кружок (красный/жёлтый/зелёный) — единственный визуальный индикатор
статуса синхронизации аккаунта (Telegram/веб) на строке «Калибровка наклона» в Настройках.
Текстовая альтернатива честно есть в коде — `l.title=…` — но HTML-атрибут `title` показывается
браузером только на `hover` (наведение курсора) и на десктопе через задержку; на тач-устройстве
(телефон/планшет, Telegram WebView) у элемента физически нет состояния «навести, не нажимая» —
`title` там не показывается никогда, только жест долгого нажатия в некоторых браузерах,
нестандартно и не гарантированно. Ни `aria-label`, ни видимый постоянный текст рядом («не
подключено»/«частично»/«готово») нигде не заданы — `grep -n "aria-label" index.html` рядом с
`calLamp` — ноль совпадений.

**Кого это касается**: дальтоника (красный/жёлтый/зелёный — классическая протанопия/дейтеранопия
путаница, хотя `COLOR-REGISTRY.md` уже закрыл дальтонизм для минералов астероидов геометрическими
маркерами — этот индикатор в тот прогон не попал, отдельный код, отдельная дата) и в первую
очередь — любого игрока на телефоне (подавляющее большинство, см. выше), у кого `title` не
работает никогда, не только при дальтонизме: даже зрячий игрок без цветовой слепоты не может
узнать текстовое значение состояния на сенсорном экране вообще, ни при какой остроте зрения.

**Почему это находка, а не гипотеза**: поведение `title`-атрибута на тач-устройствах — задокумен-
тированный факт веб-платформы, не специфика этого проекта и не требует живого скрина конкретного
устройства владельца для подтверждения (в отличие от находки 2 в angle 3 про `--sal`, где нужен
живой альбомный вырез) — сам факт «нет второго канала на тач» верифицируется чтением кода:
единственный путь узнать состояние без цвета (`title`) структурно недоступен на устройстве,
на котором играет подавляющее большинство.

**Второй заход**: `grep -n "calLamp" cosmogram-crew/tests/guard.mjs` — ноль совпадений, ни один
страж не проверяет этот индикатор вообще. `grep -in "calLamp" .knowledge/COLOR-REGISTRY.md
.knowledge/ACCESSIBILITY-GUIDE.md .knowledge/KNOWN-BUGS.md .knowledge/AI-DECISION-REGISTRY.md` —
ноль совпадений, не задокументировано нигде.

  проверка каждой пары — отдельная, гораздо более крупная задача (тот же честный пробел, что уже
  назвала `RESEARCH-2026-09-ACCESSIBILITY-WCAG-POLNY-AUDIT.md` §1: «контраст не проверялся, открыт»);
  находка 2 выше — предметный частный случай, где расхождение измеримо и локально, не попытка
  закрыть весь контраст игры одним файлом.
- **`.ptEmptyHint` (подсказка на пустой ленте Конструктора, `rgba(255,255,255,.32)`, 10px)** —
  замечено при поиске, но Конструктор целиком помечен в открытых вопросах владельца как отдельная,
  ещё не устоявшаяся область (`project_konstruktor_otkrytye_voprosy`) — не поднимаю как находку
  этого захода, слишком вероятно, что подсказка ещё будет меняться сама по себе.

## Честный итог

Четыре находки: одна о размере (`#pauseBtn`/`.menuBack` ниже собственного 36px-стандарта проекта
для круглых/±-кнопок, находка 1), одна о контрасте (`#smoothCap` вдвое менее заметен, чем соседняя
подпись того же ряда, находка 2), одна об одном канале восприятия без рабочей на тач-устройствах
альтернативы (`#calLamp`, находка 3), и одна структурная — дыра в покрытии стражей 194/195 (семь
из пятнадцати экранов и минимум два новых именных класса вне их досягаемости, находка 4). Находки
1, 3, 4 — чистое чтение кода/арифметика CSS, воспроизводимы без живого устройства. Находка 2 —
арифметика CSS-альф verified, но её визуальная СТЕПЕНЬ серьёзности честно зависит от живого
рендера динамического неба, как и было у `--sar`/`--sal` в angle 3. Переполнение перевода
(отдельный явный пункт задания) — целенаправленно проверено на самом вероятном кандидате
(`.grSendBtn`, изменённая сегодня кнопка на полноширинном контейнере) и не подтвердилось как
обрезание — только как непроверенная (не катастрофическая) разница высоты; главный практический
вывод по этой оси — не конкретный баг, а то же самое покрытие стражей из находки 4: пока экран/
кнопка не видны стражу 195, о переполнении на французском/испанском/английском узнают только по
живой жалобе, не по красному тесту. Это последний заход серии из четырёх (angle 1-4) — все четыре
готовы.
