# ✍️ Cosmogram — Style Guide & Coding Standards

> Соглашения по коду, инцидент-комментарии, Story-Comments, Conventional Commits, Zero-Allocation.
> Единственный стандарт после слияния баз: **имена в коде — английские, комментарии — русские.**

---

## 1. Общие принципы

1. **Читается как книга:** чистый модульный код без сборщиков и фреймворков. Один модуль ≈ 200 строк (максимум 300).
2. **Изоляция движка от DOM:** модули физики/математики/рендера не трогают `document`/`window`, кроме `render.js`, `input.js`, `ui.js`.
3. **Zero-GC в тике:** запрещено возвращать новые объекты `{x, y}` или массивы в тике. Поля меняются по месту, используются scratch-буферы и статические пулы.
4. **Инвариант детерминизма:** любой спавн и любая случайная величина — только внутри `withTrack(kind, fn)`.

## 2. Именование

| Сущность | Соглашение | Пример |
|---|---|---|
| Глобальные системы | `PascalCase` | `Store`, `BB`, `BEACON`, `Steering` |
| Центральное состояние | одиночная заглавная | `S`, `L` (локализация) |
| Функции и методы | `camelCase`, глагол в начале | `spawnObstacle()`, `hitPlane()` |
| Константы и капы | `UPPER_SNAKE_CASE` | `POOL_CAP`, `PARTICLE_CAP`, `STEP` |
| Таймеры/флаги табло | префикс `_mh` / `_` | `_mhTime`, `_mhOnce` |
| Координаты | `x, y, vx, vy, bank` | `plane.x`, `plane.bank` |

**Двухуровневое именование (согласовано 22.08.2026).** Для НОВОГО кода: короткие имена
`dt`/`dx`/`dy`/`vx`/`vy`/`x`/`y`/`i`/`j`/`k` допустимы только внутри горячего цикла
(`update()`/`render()` и их прямые вызовы). Везде за пределами горячего цикла — только
описательные имена, короткие сокращения там неуместны.

**Язык:** идентификаторы и имена — **на английском**; комментарии — **на русском**. (Вариант «переменные на русском» из старой базы отменён — он противоречит кодовой базе.)

**Решение по `S`/`Q`/`AC` (согласовано 22.08.2026).** Глобальное переименование этих трёх
однобуквенных имён в защищённых файлах ядра — отменено: второе мнение оценило риск в
638+ правок по всей кодовой базе, что не оправдано для чистой читаемости. `S`, `Q`, `AC`
остаются как есть навсегда, если не будет отдельного нового решения. Читаемость закрывается
комментарием-расшифровкой в начале файла, где они впервые объявлены, не переименованием.

## 3. Структура модуля

Каждый файл следует шаблону:

```javascript
'use strict';
/* ============================================================
   НАЗВАНИЕ МОДУЛЯ: краткое описание
   Версия: v1.400.2
   ============================================================ */

/* ---------- Константы ---------- */
const MAX_ASTEROIDS = 50;

/* ---------- Состояние ---------- */
let activeAsteroids = [];

/* ---------- Функции ---------- */
function spawnAsteroid(x, y) {
  // ...
}

function updateAsteroids(dt) {
  // ...
}

/* ---------- Экспорт (глобальный) ---------- */
window.ASTEROIDS = {
  spawn: spawnAsteroid,
  update: updateAsteroids
};
```

**Новые небольшие/общие JS-файлы (согласовано 22.08.2026).** Для файлов вне горячего цикла
(не `game.js`/`render.js`/`core.js`/`input.js`, а вспомогательные модули) — добавлять
`// @ts-check` первой строкой и JSDoc-типы на публичные функции. Это нулевая сборка: не
требует TypeScript, компилятора или шага сборки, только аннотации, которые понимает
редактор. Плюс баннер-комментарий «оглавление» вверху файла (как в шаблоне выше) и правило
«один файл = одна забота» — не смешивать состояние, рендер и I/O в одном модуле.

## 4. Новый экран/меню — обязательный чек-лист (02.09.2026)

Повод: баг «кнопка „Назад" не работала на экране „Написать разработчику"» — экран
(`#feedbackScreen`) был добавлен, но `backAction()` в `js/ui.js` не узнал о нём ни строкой.
Регистрация нового экрана разбросана по нескольким местам файла, между собой они никак не
связаны (ни компилятором, ни линтером) — забыть одно легко, ошибка не бросается в глаза,
пока кто-то не нажмёт именно эту кнопку на реальном устройстве.

**Обязательно всегда, без исключений — иначе экран не откроется/не закроется:**
1. HTML: `<div id="xScreen" class="overlay hidden">` + своя круглая кнопка-кружок:
   `<button class="menuBack" id="xBackBtn" aria-label="Назад"><svg class="ic" aria-hidden="true"><use href="#i-back"></use></svg></button>`.
2. `js/ui.js`, `setScreen(name)`: добавить `toggleCls('xScreen','hidden', name!=='x');` в общий
   список — без этого экран физически не появится и не спрячется.
3. `js/ui.js`, `backAction()`: добавить `else if(screenName==='x') closeX();` — без этого
   ветки нативная «Назад» Telegram молчит на этом экране (ровно этот баг, 02.09.2026).
   `closeX()` обычно = `setScreen(<откуда пришли>)`.
4. `js/ui.js`: `wireOn('xBackBtn', 'click', closeX);` — та же функция, что и в п.3, вешается
   на свою кнопку-кружок. Ghost-затухание при живой нативной «Назад» отдельно регистрировать
   не нужно — оно уже общее для всех `.menuBack:not(#firstFlightClose)`.
5. Функция открытия экрана обязана звать `setScreen('x')`, не выставлять `screenName` напрямую
   в обход — иначе `backAction()`/`pauseGhostSync()` не узнают о смене экрана.
6. **«Назад» возвращает туда, откуда РЕАЛЬНО открыли, не хардкодом в меню (17.09.2026,
   владелец: «это ж не кнопка главное меню, а кнопка назад»).** Если у экрана ОДНА точка
   входа (проверить `grep -n "setScreen('x')"` по всему репозиторию) — хардкод на неё
   технически совпадает с «откуда пришли», но честнее и живучее к будущим изменениям —
   переменная `xFrom` (тот же приём, что `settingsFrom`/`feedbackFrom`), выставляемая в момент
   открытия. Если точек входа несколько или могут появиться — `xFrom` обязателен, не хардкод.
7. **Правь ОБА пути «назад» одним заходом, не по одному (17.09.2026 — третий раз подряд один
   и тот же баг: forgeBack 08.09.2026 → аппаратная «Назад» у relayMine 15.09.2026 → круглая
   кнопка у relayMine 17.09.2026).** У каждого экрана их минимум два — круглая кнопка-кружок
   (п.4 выше) И ветка в `backAction()` (нативная/аппаратная «Назад» Telegram, п.3) — при
   удалении/переименовании промежуточного экрана искать оба места СРАЗУ (`grep -n
   "setScreen('<старое-имя>')"` по всему репозиторию), не только то, что заметил игрок на
   этот раз.
8. **Кастомный заголовок (не общий `.screenTitle`) — своя защита от наезда на «Назад»
   (17.09.2026).** `.screenTitle` уже имеет `max-width:calc(100% - 96px)+margin:auto` под
   круглую кнопку слева — если экран использует СВОЙ класс заголовка (как `#forgeStepTitle`),
   эту защиту нужно скопировать явно, она не наследуется просто по соседству в разметке.

**Не единый рецепт — сверяться с похожим соседним экраном, а не копировать вслепую:**
- Тёмная вуаль фона (`background:rgba(6,10,24,.45)`, общий селектор со всеми экранами меню) —
  есть у всех, добавить свой id в этот список.
- `padding-top:var(--menu-top-pad)` — нужен экрану С заголовком вверху (большинство). Не нужен
  экранам без заголовка (пример: `#cardScreen`).
- Скроллящийся длинный контент (`justify-content:flex-start` + `overflow-y:hidden` +
  `>* {flex-shrink:0}` + `>.scrBody {flex-shrink:1}`, один и тот же список экранов во всех
  четырёх местах: `settingsScreen, achScreen, hangarScreen, forgeScreen, diagScreen,
  feedbackScreen`) — нужен, только если контент может не влезть на маленьком экране. Короткие
  центрированные экраны (`cardScreen`; `modesScreen` был тем же примером, удалён 15.09.2026) этого не имеют вовсе.
- `pointer-events:auto` на весь контейнер (список: `settingsScreen, achScreen, hangarScreen,
  gameOverScreen, forgeScreen, diagScreen, feedbackScreen`) — нужен, только если внутри есть
  НЕ-`.btn` интерактив (виджеты входа, спойлер, скролл жестом) — у `.btn` уже свой собственный
  `pointer-events:auto`. Если весь клик идёт через `.btn`/подобные классы — контейнерный auto
  не нужен (пример: `cardScreen` работает без него; `modesScreen` был тем же примером, удалён 15.09.2026).

Любая правка этих файлов — версия (`GAME_VERSION`+`sw.js`+`index.html ?v=`) бампается как
обычно, страж (`tests/guard.mjs`) по тому же правилу «до фикса», что и для игрового кода.
