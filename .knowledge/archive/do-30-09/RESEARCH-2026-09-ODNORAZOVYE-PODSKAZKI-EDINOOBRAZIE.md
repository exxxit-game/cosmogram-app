# Одноразовые подсказки: сколько их и насколько они разные (19.09.2026)

Владелец попросил (а) добавить одноразовую подсказку-название на каждую иконку
фильтра в Конструкторе (новые/вау/растёт/избранное/случайно) и (б) заодно
проверить, что ВСЕ такие подсказки в игре ведут себя одинаково — «не надо, чтобы
она долго светилась», предположил 5 секунд, спросил, есть ли исследования.
Разбор — только чтение кода, без правок.

## 1. Что уже есть в игре — семь разных одноразовых подсказок

Все используют один и тот же Store-флаг-паттерн («видел один раз — не показывать
больше», навсегда, ключ в `Store`), но **делятся на два непохожих типа по способу
скрытия**:

| Подсказка | Файл | Флаг | Как гаснет |
|---|---|---|---|
| `angarWalletTip` (кошелёк в Коллекции) | ui.js:3755-3758 | `angarWalletTipSeen` | Только при выходе с экрана (`hangarLeave`) — **таймера нет вообще** |
| `ptMoodHint` (Настроение в Тюнинге) | forge.js:1001-1006 | `forgeMoodHintSeen` | Не гасится сама — висит, пока не сменится экран/состояние |
| `forgeFavHint` (Избранное пусто) | forge.js:1007-1012 | `forgeFavHintSeen` | Гасится, когда список перестаёт быть пустым — **не по времени** |
| `workshopEditHint` («Изменить» в Мастерской) | forge.js:1589,1648 | `workshopEditHintSeen` | По первому тапу «Изменить» — действие, не время |
| Клавиатура «одна рука» | input.js:803-806 | `keysOneHandSeen` | Через общий `toast()` — **авто-скрытие через 1.5 сек** (дефолт `ms||1500`) |
| Обычный `toast()` (много мест) | core.js:214-221 | — (не одноразовый сам по себе, но так вызывается тостами-подсказками) | Авто, `ms||1500`, необязательный 3-й параметр `ms` (05.09.2026: подсказки-факты в Тюнинге держат дольше 1.5с, т.к. текст длиннее) |
| `welcomeShow`/`streakDayCheck` (раз в день, не раз навсегда) | core.js:730-757 | `welcomeDay`/`streakDay` | Другой класс задачи (не «подсказка про элемент», а «событие дня») — не считаю в этом списке как аналог |

**Вывод:** подсказки НЕ единообразны. Пять из шести — либо не имеют таймера вовсе
(живут, пока не сменится экран/состояние/действие — потенциально минуты, если
игрок завис на экране), либо используют `toast()` с дефолтом **1.5 секунды**, не
5. Совпадение с предположением владельца (5 сек) — не подтверждается ни одним
реальным местом в коде. Это не выдумка «на глаз» — общий `toast()` уже 05.09.2026
получил переменную длительность именно потому, что 1.5с оказалось мало для более
длинного текста (см. комментарий в core.js:214) — то есть даже внутри ОДНОГО
механизма уже есть прецедент «текст длиннее → время больше».

## 2. Что говорят реальные рекомендации по времени показа

Не выдумано, общеизвестные источники (веб-доступность/UX, не специфично для
Cosmogram):

- **WCAG 2.2.1 «Timing Adjustable»** — если у контента есть лимит по времени,
  пользователь должен суметь его продлить/выключить/убрать таймер, ЕСЛИ время не
  «существенно» (essential) для задачи. Чистая информационная подсказка, которую
  нельзя продлить и она просто исчезает — формально спорна с точки зрения
  доступности, особенно для игроков с медленным чтением (та же аудитория, что уже
  учтена в [[feedback_comfort_for_everyone]] — дети/пожилые/люди с ограничениями).
- **Material Design (snackbar/toast)** — рекомендует 4–10 секунд для коротких
  сообщений без действия, дольше при наличии кнопки-действия внутри.
- **Nielsen Norman Group** (общее правило для не-критичных всплывающих
  сообщений) — ориентир «достаточно времени прочитать текст дважды», грубо
  ~1 секунда на 3 коротких слова плюс запас; для однословной подписи типа «Новые»
  это может быть даже меньше 2 секунд, но для «Набирают популярность» — больше.

## 3. Развилка, которую решать владельцу (не мне)

Два разных вопроса зашиты в одном пожелании:

1. **Таймер vs действие.** Сейчас 5 из 6 подсказок гасятся ДЕЙСТВИЕМ игрока
   (сменил экран, тапнул кнопку, список заполнился) — не временем. Только
   клавиатурная подсказка живёт по таймеру (1.5с, через общий toast). Если
   ввести именно ТАЙМЕР для новых иконок-подсказок — это НОВЫЙ для большинства
   существующих случаев механизм, не расширение существующего.
2. **Сколько именно секунд**, если таймер — единого готового числа в проекте
   нет (1.5с — это дефолт toast для коротких служебных сообщений, не про
   «объясни, что означает иконка»).

Правка не делалась (только исследование, как договорено правилом
[[feedback_issledovaniya_v_knowledge]]). Годится как основа для отдельного макета
подсказок-иконок Конструктора + решения по стандарту таймера для всей игры —
оба вопроса лучше развести на два отдельных «да», не мешать в одну правку.
