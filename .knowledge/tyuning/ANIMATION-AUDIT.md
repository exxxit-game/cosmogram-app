# Аудит «что можно/нужно анимировать» — все скины на 06.09.2026

Запрошено владельцем 06.09.2026: разобрать ВСЕ построенные макеты (не только что-то одно) и
для каждой карточки сказать — стоит ли её вообще анимировать, до того как код для этого
кто-то будет писать. Ничего из этого не реализовано, это только анализ.

## Правило (установлено в диалоге с владельцем)

Жёсткое техническое условие после фриза телефона на перпетуальном 60fps-цикле: любая будущая
анимация — ТОЛЬКО ограниченная по времени (сыграла один раз/N раз и остановилась) либо с
паузой, когда карточка не видна. Никогда не «вечный» requestAnimationFrame-цикл на всю жизнь
страницы.

Критерий «стоит ли анимировать» — не «а можно ли», а: **реальное явление ОПРЕДЕЛЯЕТСЯ
процессом/движением во времени** (рост, вращение, распространение волны, самоорганизация) —
тогда статичный кадр буквально теряет суть явления, анимация это не декорация, а часть факта.
Если явление — это фиксированный факт (форма, угол, счёт, симметрия), анимация — просто
шевеление без научного смысла. Отдельная категория — карточки, где смысл ИМЕННО в
застывшести (звёздные треки, хронофотография): их анимировать нельзя, это исказит факт.

Обозначения: 🎬 — сильный кандидат (явление буквально определяется движением/временем),
🎬? — умеренный/опциональный кандидат (можно, необязательно, есть честная привязка к факту),
⛔ — НЕЛЬЗЯ анимировать (сама суть — застывший момент), — — статичный факт, анимация не
добавляет смысла.
