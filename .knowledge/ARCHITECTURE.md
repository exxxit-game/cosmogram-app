# 🏗️ Cosmogram — Архитектура игры (актуальное устройство)

> Документ описывает только то, что существует в сборке. Отброшенные идеи — в отдельном разделе внизу.

---

## 1. Версия

- Версия и число стражей не хранятся здесь как числа — они меняются с каждым релизом.
  Смотрите живьём: `GAME_VERSION` в `core.js` (версия), длина реестра в `tests/guard.mjs`
  (число стражей). Известные пробелы в реестре стражей — см. `KNOWN-BUGS.md`.

## 2. Стек

- **Чистый Vanilla JavaScript**, без сборщиков, фреймворков, TypeScript, WebGL и WASM.
- **Каскад из 18 скриптов**: ядро (`core.js`, `game.js`, `render.js`, `input.js`) плюс модули расширения (forge, achievements, adaptive, composer и другие) — подключаются по порядку, общаются через глобальные системы.
- **Рендер — Canvas 2D**, один основной канвас, масштабирование под DPR с потолком 2560 px по длинной стороне.
- **Платформа — Telegram Mini App** (iOS/Android WebView) и десктопные браузеры. **PWA (Service Worker) выключен осознанно** с v1.20.0.

## 3. Состояние и детерминизм

- Центральное состояние — объект **`S`**; локализация — **`L`**.
- Все случайные величины — только через **`mulberry32`** с явным сидом, внутри **`withTrack(kind, fn)`**: каждая категория спавна (препятствия, звёзды, бонусы) имеет изолированный поток чисел, утечки между потоками запрещены.
- Запрет `Math.sin/cos` в спавне трассы — только целочисленный LUT (округления V8 и JavaScriptCore не совпадают).
- Трасса дня детерминирована общим суточным сидом; протокол seed гарантирует одну и ту же геометрию на любом экране.

## 4. Игровой цикл

- **Fixed Timestep:** шаг физики `STEP = 1/60` с аккумулятором; рендер не влияет на физику.
- Интерполяция остатка (alpha) между тиками — запланирована, пока не внедрена (см. KNOWN-BUGS).
- Спящая пауза: в полёте 60/120 FPS, в меню ~30, на паузе после двух секунд ~4 FPS.

## 5. Память и пулы

- Zero-GC в тике: никаких аллокаций в `update()`/`render()`.
- Лимиты пулов: **64 / 64 / 16 / 120–220 / 32**; частицы масштабируются по тиру устройства (низкий 120, средний 180, флагман 220). Назначение лимита 32 в базе знаний не расшифровано.
- Объекты возвращаются в пул чистыми: сбрасываются `_tint`, `_path`, `_tg`.
- Удаление из массивов — Swap-and-Pop за O(1).

## 6. Хранилище

- **Store двухуровневый:** лёгкие ключи и агрегированные максимумы — в Telegram CloudStorage (до 4 КБ на ключ), тяжёлые данные (ленты призраков) — в `localStorage` и на сервере.
- Любое обращение к хранилищу — под `try/catch` (урок инцидента B1: запрещённое хранилище убивало взлёт до чёрного экрана).

## 7. Сервер и телеметрия

- **Supabase Edge** (проект eu-central-1), функции синхронизации; версия `cosmogram-sync` в бою не хранится здесь — меняется с каждым деплоем, смотреть через Supabase MCP `list_edge_functions` живьём.
- Телеметрия — через `beacon.js`: очередь с батчингом писем в один запрос, окно вежливости 21 секунда, дедупликация ошибок за сессию, досылка при следующем старте.
- `sessionBeacon` доходит: подтверждено живым кодом 24.08.2026 (106 строк `kind='session'` в базе на тот момент) — см. KNOWN-BUGS.md, было ошибочно помечено «не долетает» в более раннем аудите этого файла.

## 8. Призраки и запись

- Запись забега — лента кадров (10 кадров на пакет) с квантованием в 92 уровня.
- Детерминизм «зерно + лента» позволяет покадрово воспроизвести любой заезд; Театр призраков — зрительский автопилот по записи.
- Призраки разбиты по категориям (keys / bullet / dist / обычные).

## 9. Звук

- **Процедурный Web Audio:** ноль аудиофайлов, всё синтезируется в рантайме.
- Музыка — эмбиент по минорной пентатонике, четыре слоя (дрон, пыль, напряжение, события), сайдчейн-приглушение на Сверхновой и ударах.
- Звук подчинён детерминизму: аудио-поток сидируется тем же ключом трассы.

## 10. Доступность и управление

- **Пять штурвалов:** палец, гироскоп (с Судом компасов), мышь, клавиатура, геймпад.
- Профили неба (стандартное, тихое, спокойное, ясное, дальтоник), две категории рекордов.
- Общий тумблер согласия на датчики; тумблер отключения наклона — открытый долг (см. KNOWN-BUGS).

## 11. Стенд и релиз

- Стенд: `tests/guard.mjs` (число стражей — смотреть в файле, растёт с релизами), три прогона, ключ `--only=<маска>`.
- Релизная синхронизация: `bump_version.py` обновляет 20 мест — `sw.js`, `GAME_VERSION`, все теги `?v=`; обязательный финальный шаг каждого релиза.
- Приборы стенда (у экипажа — десять; поимённо в документах названы девять):
  `guard.mjs` (стражи), `playtest.mjs` (темп/плотность/коридор), `eyes.mjs` (кадры на трёх
  устройствах), `profile.mjs` (замер кадра под замедлением CPU), `pervaya-minuta.mjs`
  (первые волны), `pervye-tri.mjs` (первые преграды по 200 сидам), `tesnota.mjs`
  (сколько UI не помещается), `ochnaya-stavka.mjs` (две сборки на одной мерке),
  `relizy.mjs` (деление дерева: наружу — только игра).

## 12. Что НЕ является частью игры (отброшенные идеи)

- WebGL / WebGPU / WASM — вердикт проекта: не мигрировать.
- PWA / офлайн-режим — выключен осознанно.
- TypeScript — проект остаётся чистым JS.
- ~~Ветка `GHOSTS_VISIBLE` — откачена~~ — устарело: восстановлена и работает, `ghostActive()`
  честно читает `Store.ghostAgain` (auto/1/0) — см. KNOWN-BUGS.md, AI-DECISION-REGISTRY.md T5.
  «Партии 29–32» (сам патч-набор, отдельно от ветки) статус не проверялся в этом заходе.
- Адаптивная сложность под игрока — заменена детерминированным ритмом трассы, общим для всех.
