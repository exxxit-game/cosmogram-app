# CI/CD для Cosmogram

## Что настроено

### GitHub Actions
Файл `.github/workflows/ci.yml` запускает автоматические тесты при:
- Пуше в ветки `main` и `master`
- Создании Pull Request

### Как это работает

1. **При каждом коммите** GitHub запускает виртуальную машину с Ubuntu
2. **Устанавливается Node.js 20** и Puppeteer (headless Chrome)
3. **Загружается игра** в браузере без графического интерфейса
4. **Выполняются тесты** через `tests/run-ci.js`
5. **Результат сохраняется** в артефакты (при провале)

### Структура файлов

```
cosmogram-app/
├── .github/
│   └── workflows/
│       └── ci.yml              ← Конфигурация GitHub Actions
├── tests/
│   ├── run-ci.js               ← Скрипт запуска тестов в CI
│   └── *.test.js               ← Файлы тестов (19 штук)
├── package.json                ← Зависимости и скрипты npm
└── index.html                  ← Игра (добавлен флаг gameLoaded)
```

### Статусы тестов

| Статус | Значение |
|--------|----------|
| ✅ Прошло | Все тесты зелёные, можно мержить |
| ❌ Провалено | Есть ошибки, нужно исправить перед мержем |
| ⏳ В процессе | Тесты ещё выполняются |

### Как проверить локально

```bash
# Установить зависимости
npm install

# Запустить тесты
npm test

# Или напрямую
node tests/run-ci.js
```

### Добавление новых тестов

1. Создай файл `tests/название-теста.test.js`
2. Напиши тест в формате Node.js с `assert`
3. CI автоматически подхватит его при следующем запуске

### Артефакты

При провале тестов GitHub сохраняет:
- `test-results.json` — подробный отчёт о каждом тесте
- Логи ошибок консоли

## Правила

1. **Нельзя мержить код с красными тестами** — CI заблокирует пулл-реквест
2. **Новые функции = новые тесты** — минимум 1 тест на фичу
3. **Рефакторинг не должен ломать тесты** — если сломал, сначала обнови тесты

## Troubleshooting

### Тесты падают только в CI

Возможные причины:
- Разница в часовых поясах
- Особенности headless-браузера
- Отсутствие некоторых API в CI-окружении

Решение: добавь проверку окружения в тест:
```javascript
if (process.env.CI) {
  // Специфичная логика для CI
}
```

### Puppeteer не устанавливается

Попробуй:
```bash
npm install puppeteer --save-dev --ignore-scripts
npx puppeteer browsers install chrome
```

### Тесты выполняются слишком долго

Оптимизация `ci.yml`:
- Уменьши таймауты ожидания
- Кэшируй node_modules между запусками (уже включено!)
- Используй `actions/cache` для зависимостей

## 🔥 Кэширование: зачем и как работает

### Что такое кэширование node_modules?

**Проблема:** При каждом запуске CI GitHub скачивает все зависимости (~100-200 МБ для Puppeteer). Это занимает 30-60 секунд.

**Решение:** GitHub сохраняет папку `node_modules` после первого запуска. Следующие запуски восстанавливают её за 5-10 секунд.

### Как это работает в нашем конфиге:

```yaml
- name: Setup Node.js
  uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm' # ← Эта строка включает кэширование!
```

GitHub автоматически:
1. **Сохраняет кэш** после успешной установки зависимостей
2. **Восстанавливает кэш** при следующем запуске (если `package-lock.json` не изменился)
3. **Обновляет кэш** только если изменились зависимости

### Экономия времени:

| Запуск | Без кэша | С кэшем |
|--------|----------|---------|
| Первый | 60 сек | 60 сек |
| Второй | 60 сек | 10 сек ⚡ |
| Третий | 60 сек | 10 сек ⚡ |

**Итого:** Экономия ~50 секунд на каждый запуск после первого!

### Когда кэш сбрасывается:

- Изменился `package-lock.json`
- Прошло 7 дней без использования (автоматическая очистка GitHub)
- Вручную через настройки репозитория
