# Хуки, правила и память: как разделить по задачам (исследование 02.10.2026)

Заказ владельца 02.10: хуки по смыслу одинаковые, часть не нужна, игровые запреты ассистенту при работе со скинами не нужны; хочется набор «для моих задач» и набор «для правки игры», связанный с памятью и документами. Ничего в проекте не менялось.

## 1. Что подтверждено документацией (прочитано первоисточником, не пересказом)
Источники: code.claude.com/docs/en/hooks-guide, /memory (02.10.2026).
- Все подходящие хуки одного события идут **параллельно**; решения PreToolUse: deny > defer > ask > allow.
- Поле `if` у хука (`"if": "Bash(git *)"`, `Edit(*.ts)`) не запускает процесс, пока вызов не подходит. Работает только на PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied; на других событиях хук не запустится вообще.
- Хуки в шапке скилла живут **до конца сессии после вызова скилла**, не «пока скилл активен». Хуки в шапке субагента: пока он работает. `--agent` запускает роль со своими хуками рядом с общими. Не проверено: как это в приложении Claude на этой машине.
- Слои настроек (проект, локальный, пользовательский) **складываются**, не заменяют. Выключателя одного хука нет, только `disableAllHooks` на всё.
- Что доходит до ассистента: exit 2 + stderr (PreToolUse, Stop); `additionalContext` внутри `hookSpecificOutput`; stdout на UserPromptSubmit и SessionStart. **stderr при exit 0 до ассистента не доходит**, `systemMessage` видит владелец.
- Stop-хук: надо проверять `stop_hook_active`; после 8 блокировок подряд Claude Code сам завершает ход.
- `.claude/rules/*.md` с `paths:` грузятся, когда читается подходящий файл (не на запись, не на каждое действие).
- CLAUDE.md: до 200 строк, дальше хуже соблюдается; импорт `@файл` грузится целиком на старте, контекст не экономит. MEMORY.md: первые 200 строк или 25 КБ. Темы читаются по запросу.
- Окно «Instructions for Claude» в настройках аккаунта claude.ai в документации Claude Code **не упомянуто**; читаются CLAUDE.md, rules, папка памяти. Связи с Claude Docs в документации нет.
- Хук, печатающий в контекст то, что Claude и так читает файлом, даёт дубль.

## 2. Замеры (мои, 02.10, Windows, `hook-timing.mjs`, медиана 5 запусков)
- `.sh`-хуки 500–1200 мс каждый (Git Bash), `.mjs` 150–300 мс.
- На каждую команду Bash 6 хуков до неё и 1 после, около 35 процессов; последовательно 4,6 с, если параллельно около 1,2 с.
- Stop: 3 хука, 0,5 с.
- Вне нашего проекта чужой замер: тормозит время одного хука, не число (DEV 20.08.2026; ruflo #1530).

## 5б. Второй заход: поиск на языках мира (02.10.2026, 11 помощников, лимит поиска сессии 200 исчерпан)
Содержательные первичные работы нашлись только на английском; китайские, японские, корейские, русские, немецкие, тюркские, арабские и др. источники по сути пересказывают их или дают личный опыт без замеров. Сверено мной по первоисточнику (arXiv/страницы):
- Compaction Cliff, arXiv 2608.22752 (CIKM 2026): после /compact в Claude Code сохраняется 53% правил за один раунд, 10% за пять. Правила в беседе теряются.
- Guardrails Beat Guidance, arXiv 2604.11088 (13.04.2026, Claude Opus 4.6, SWE-bench Verified, 5 000+ запусков): случайные правила дают +13,8 п.п. так же, как экспертные; каждое полезное правило запрет («не рефакторь постороннее»), каждое вредное предписание («следуй стилю»).
- ContextCov, arXiv 2603.00822 (300 задач): жёсткая проверка снаружи 88,3%, только текстом 67,0%, «перепроверь себя» 50,3%.
- Escalation channels, arXiv 2608.29460 (29.08.2026): если дать агенту легальный способ сообщить о дефекте, жульничество упало с 23,6% до 5,3%, 98,7% сообщений без жульничества.
- Cross-model review, arXiv 2610.01471 (01.10.2026): один свежий ревьюер той же модели плюс ревьюер другой модели нашли 56,7% ошибок против 42,7% у двух ревьюеров той же модели.
- Config Smells, arXiv 2606.15828 (UFMG, 100 репо): lint leakage 62%, context bloat 42%, skill leakage 35%.
- Vercel 27.01.2026 (56% не вызван; 53/53/79/100) и Scott Spence 08.02.2026 (55/59/100): сверено ранее.
Со слов помощников, оригинал не открывал: Kraishan 2609.12205 (в самоотчёте агента упомянута примерно 1 из 11 операций, отчёт подтягивается к плану); SkillsBench 2602.12670 (скиллы в кодинге дают скромный выигрыш, 4+ скиллов хуже 1–3, скиллы, сочинённые агентом, не помогают); SWE-Skills-Bench 2603.15401 (39 из 49 скиллов без прироста); McMillan 2605.10039 (длина файла не влияет, каждая следующая функция в сессии −5,6% к соблюдению); Treude/Baltes 2606.09090 (устаревшие ссылки в 23% файлов); Harness-IF 2608.11727 (правила против привычки модели хуже на 3,6–7,4 п.п.).
Не подтверждено и выброшено: «3,5% открывают файлы правил сами» (в работе 2607.26819 этого нет); «0/30/59% нарушений после сжатия» (vc.ru, источника нет); «рассуждающие модели не защищены» (не в аннотации).

## 5в. Официальное руководство Anthropic для Sonnet 5.5 (сверено дословно, 02.10.2026)
platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5-5. Готовые абзацы для наших бед: (1) «когда сделано и проверено, остановись и отчитайся, не добавляй функции, тесты, файлы, доки, рефакторинг, которых не просили, упомяни в конце»; (2) «запусти реальную проверку изменения; если никакая проверка не может быть запущена, скажи, какую не запускал и почему, вместо "готово"»; (3) «когда просят идеи, варианты или план, дай их и остановись, ничего не меняй, пока не скажут "делай"»; (4) при низком effort модель иногда пропускает проверку. Постмортем Anthropic (anthropic.com/engineering/april-23-postmortem): жалобы марта–апреля 2026 были из-за смены effort high→medium (04.03, откат 07.04), бага кэша, из-за которого модель забывала и повторялась (26.03, исправлено 10.04, версия 2.1.101), и ограничения «≤25 слов» в системном промпте (16.04, откат 20.04). Наши жалобы с 26.08, к тому периоду не относятся.
Не сверено, со слов помощника: «80%+ системного промпта Claude Code убрано без потери качества (24.07.2026, домен claude.dev)»; Thoughtworks Radar 04.2026 «Agent instruction bloat» в зоне «Осторожно»; Augment: плохой файл правил хуже отсутствия, 30+ правил «не» без решения удваивают время.

## 6. Предложение (ждёт слова владельца)
Роль определяется тем, чего касается действие (путь, команда), а не переключателем. Семь диспетчеров на node вместо 53 файлов; общий набор минимален; `if` по путям; Stop-хуки смотрят только то, что изменилось в этом ходу. Подробности и порядок шагов в ответе владельцу 02.10.
