# ♿ Руководство по доступности (Accessibility & Inclusive Design)

> **Стандарт:** WCAG 2.1 AA Compliance & Device Inclusion  
> **Миссия:** Играть может каждый — на любом экране, в любых условиях и при любых физических ограничениях.

---

## 1. Разблокировка масштабирования текста (v1.108.1 Fix)

В версии v1.108.1 устранена критическая преграда для слабовидящих игроков:

```html
<!-- БЫЛО (блокировало зум везде): -->
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover"/>

<!-- СТАЛО (соответствует стандарту WCAG 1.4.4): -->
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover"/>
```

**Решение:**
- В меню, витринах и настройках слабовидящие пользователи могут свободно масштабировать интерфейс.
- В активном полёте случайный жест масштабирования блокируется локально через CSS-свойство `touch-action: none` на контейнере холста.

| Канал | Реализация | Для кого предназначено |

## 3. Профили доступности в настройках

1. **Стандартное небо:** Полный спектр визуальных эффектов и частиц.
2. **Тихое небо:** Отключение звука с переносом всей информации на виброэфир и вспышки интерфейса.
3. **Спокойное небо (`prefers-reduced-motion`):**
   - Отключение тряски экрана при ударах.
   - Плавное гашение пульсации световых конусов и щита.
4. **Ясное небо (Высокий контраст):**
   - Усиленные силуэты астероидов.
   - Четкие монохромные рамки и маркеры ворот.
5. **Режим дальтоника:**
   - Минеральные тона астероидов дублируются геометрическими маркерами (снежинка для льда, гайка для железа).

## 4. Чеклист проверки доступности

- [ ] В меню настроек работает системный зум браузера/ОС.
- [ ] Все интерактивные кнопки имеют размер touch target ≥ 44×44 px.
  ⚠️ **Нарушение найдено 27.08.2026:** `#overQuiet .btn` (`index.html:874`) — кнопки «Вызов» и

- [ ] При включенном `prefers-reduced-motion` тряска экрана отключена.
- [ ] Сигналы морзянки тактильно различимы без звука.
- [ ] Игра переведена на 5 языков (RU, EN, ES, FR, PT) с корректными манифестами PWA.

## 5. Управление наклоном и Motion Actuation (WCAG 2.5.4)
**Требование:** Функциональность, управляемая движением устройства, должна также управляться через UI-компоненты, и должна быть возможность отключить реакцию на движение.

**Настройка чувствительности и мёртвой зоны:**
- Два ползунка: чувствительность (регулировка ±50% от дефолта, согласно Xbox Accessibility Guidelines) и мёртвая зона (порог, ниже которого движение игнорируется).  
- Пресеты калибровки (как в Tilt to Live): Regular (обычная поза), Top-Down (телефон над лицом), Sleepy (лёжа).  
- Автокалибровка на старте ненадёжна — лучше предложить выбор пресета.
- ⚠️ **Расхождение документа и кода, найдено 27.08.2026.** Этот раздел описывает требование,
  не боевое поведение. В `js/gyro.js` ни ползунков чувствительности/мёртвой зоны, ни пресетов
  калибровки нет вообще — только тост «откалибровано» (`gyro.js:170`) на однократный сброс нуля.
  Раздел был прочитан как «уже сделано», это неверно — задача открыта.

## 6. Звук и физический переключатель тишины на iOS
- Физический переключатель «Тишина» на iPhone блокирует весь Web Audio, и это нельзя обойти программно.
- **Открытый вопрос, найдено 27.08.2026, требует решения владельца.** `github.com/feross/unmute-ios-audio`
  утверждает, что короткий беззвучный сэмпл через `<audio>`-тег на пользовательском жесте включает
  Web Audio «в тех же условиях, где HTML5 `<audio>` уже работает при включённом переключателе
  Тишины». Это НЕ программный обход аппаратной блокировки — сама библиотека признаёт, что
  использует негарантированную, недокументированную особенность `<audio>`-тегов на iOS, которая
  может отличаться по версиям; собственные рекомендации Apple — уважать переключатель, не обходить
  его. Статус актуальности для свежих iOS не подтверждён. Не внедрено — решение, стоит ли вообще
  исследовать этот путь, за владельцем.  
- В интерфейсе должна быть подсказка: «Проверьте, что переключатель Тишина выключен, если звук не работает».

## 7. Скринридеры и Canvas 2D — не проверялось до 27.08.2026

Игра целиком рисуется на одном `<canvas id="game">` (`index.html:1095`) — по природе Canvas 2D
невидим для скринридеров (пиксели, не DOM). Это отдельная, более узкая проблема, чем визуальная/
моторная доступность выше — раньше ни разу не проверялась специально.

- **Сонар-радар из §2/CHARTER.md ст.8-9 — роадмап, не код.** Grep по `js/*.js` на
  `sonar|radar|эхолокац|beep|proximity|ping` — ничего похожего на игровую механику близости для
  незрячих не найдено. В `AI-ROADMAP.md:53` этот же «звуковой сонар» прямо помечен пунктом
  роадмапа. Устав/чек-лист описывают цель, не факт реализации — не путать одно с другим.
- **Главный `<canvas>` без единого атрибута доступности** — ни `role="img"`, ни `aria-label`,
  ни fallback-контента внутри тега. Дёшево чинится одной атрибутной правкой (не требует переделки
  рендера), не сделано.
- **`aria-live` есть только для `#toast`** (UI-подсказки), не для игровых событий (счёт/смерть/
  рекорд). Официальный паттерн W3C для игр — `aria-live` только на дискретные редкие события
  (пауза, конец забега), НЕ в реальном времени 60 кадров/сек (убьёт и скринридер, и производительность,
  человек физически не успеет расслышать). Реалистичный минимум — подключить объявление результата
  забега к уже существующему `#toast` в момент конца забега, не переделывать rendering loop.
- **Полная играбельность вслепую (аудио-эхолокация в реальном времени)** технически существует
  как жанр (Blind Drive, A Blind Legend), но это игры, спроектированные под звук с нуля — для
  аркадного раннера на Canvas это переписывание игрового цикла, не a11y-патч. Не рекомендуется
  как задача «дёшево и сейчас» — отдельное архитектурное решение по отдельному явному запросу.
- **Юридически, проверено 27.08.2026:** WCAG 2.1 SC 1.1.1 (Non-Text Content) не содержит
  исключения для игр (расхожее мнение об «исключении» не подтверждается текстом стандарта,
  w3.org/TR/WCAG21). European Accessibility Act (в силе с 28.06.2025) видеоигры как таковые прямо
  НЕ включает в Annex I — требования цепляются за встроенный e-commerce/чат-сервисы, не за сам
  геймплей. Для Cosmogram (Stars-монетизация уже отложена владельцем отдельно) юридического
  давления сейчас не видно ни по ADA (США, только CVAA про чат/коммуникацию), ни по EAA — риск
  низкий, но это не повод откладывать пункты выше, они дёшевы сами по себе.

## 7. Тактильная обратная связь
- `navigator.vibrate()` не работает на iOS (Safari/WebKit).  
- Используйте `Telegram.WebApp.HapticFeedback`, но он нестабилен на Android.  
- **Тактильный отклик не должен быть единственным каналом информации** — дублируйте визуально и звуком.

## 8. Приминг разрешений для датчиков
- На iOS запрос разрешения на `DeviceOrientation` должен происходить из обработчика жеста (например, кнопка «Играть»).  
- Рекомендуется показывать собственный экран-объяснение перед системным диалогом (приминг) — по данным NN/g это повышает согласие на 12%.  
- В случае отказа предложите альтернативное управление.

## 9. Screen shake (дополнение)
- Тряска экрана — триггер укачивания.  
- У нас уже есть отключение при `prefers-reduced-motion`, но стоит добавить отдельный тумблер для ручного отключения.
