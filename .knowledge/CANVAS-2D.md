# 🎨 Canvas 2D в Cosmogram — сводка правил

> Быстрая памятка. Полный свод — в PERFORMANCE.md; первоисточники-конспекты — в ARTICLES/ (optimizing-canvas, html5-canvas-oreilly, eloquent-javascript-canvas).

## Золотые правила (кратко)

1. **Ноль объектов в игровом цикле.** Пулы для астероидов, частиц, бонусов, звёзд. `new`, `{}`, `[]`, `.map()/.filter()` в тике запрещены.
2. **Offscreen canvas для статики.** Фон, туманности, свечения — предрендер один раз, в кадре только `drawImage`.
3. **Минимум `save()/restore()`.** Сброс — `setTransform(1,0,0,1,0,0)`; батчинг отрисовки по стилям (fillStyle, globalAlpha, composite-режимы группируются).
4. **`toDataURL()` — только вне цикла.** Для карточки — `toBlob()` через Promise.
5. **Кэш вычислений.** LUT для sin/cos/atan2; силуэты астероидов — в Path2D при спавне.
6. **Размер canvas не меняется в полёте.** Resize — между экранами, с дебаунсом через rAF.
7. **Целые координаты** в drawImage (`x | 0`); снап только визуала, не симуляции.
8. **DPR с потолком.** `dpr = min(devicePixelRatio, 2)`; «Потолок листа» 2560 px по длинной стороне.
9. **Только `requestAnimationFrame`.** Никогда setTimeout/setInterval для цикла.
10. **Клиппинг и спрайты.** Сложный clip — предрендер в offscreen; спрайт-атласы с padding 1–2 px от bleeding.

## Слои отрисовки (порядок)

Очистка → фон (offscreen) → параллакс → препятствия → игрок → бонусы → частицы → UI.

## Пороги и решения (стратегический вердикт)

- 10–50 объектов: Canvas 2D достаточно. 50–200: зона Cosmogram, нужен Path2D-кэш и батчинг. >200: рассмотреть гибридный слой частиц. >1000: только тогда WebGL.
- WebGPU/OffscreenCanvas-worker — не внедрять (оверхед для раннера). HTML-in-Canvas — не внедрять (Chrome-only).
- Один совет «на будущее»: интерфейс Renderer как паттерн Strategy, чтобы гипотетическая миграция не трогала логику. Не внедрять, пока не потребуется.
